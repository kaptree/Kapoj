# UI-19 / UI-20 PrimeVue 迁移 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成 UI-19（题库编辑/测试点/样例）与 UI-20（403/404 异常页）的 PrimeVue 4 迁移，并移除 Element Plus 依赖与过渡样式。

**Architecture:** 沿用现有 `AppPageHeader`/`AppSurface`/`AppFormField`/`AppEmptyState`/`AppErrorState`/`AppLoadingState` 与 PrimeVue 4 组件，原地重写四个页面/组件，保留现有 API、路由、权限、props/emit 与测试点/样例行为；最后从 `main.ts`、`package.json`、lockfile 与全局样式移除 Element Plus。

**Tech Stack:** Vue 3、TypeScript、Vite、PrimeVue 4、Vitest、Vue Test Utils、pnpm workspace。

**Spec:** `docs/superpowers/specs/2026-11-08-ui-19-20-primevue-design.md`

## Global Constraints

- 分支 `feat/ui-19-20-primevue`（基于已本地合并 M5-4 的 `main` `c9855dc`）；不推送/合并，除非用户确认。
- 只改前端；不改后端、API、OpenAPI、路由 path/name（UI-20 仅可补 `not-found` 的 `meta.title`）、权限、Pinia、SSE、localStorage、上传字段/大小限制。
- 保留 `TestcaseManager` props `{problemId,type,checkerUploaded}` 与 emit `changed`；保留 AI 造数据入口与 `problem-testcase-generator` 路由。
- 保留 `ProblemEditView` 的 `reactive<Required<ProblemInput>>` 表单、保存/创建/删除/跳转/错误恢复逻辑；不新增客户端校验规则。
- 样例最多 10 组；测试点输入/输出各 ≤16 MiB；checker ≤256 KiB；分数 0–1000；题目 tags 最多 10 个。
- 新页面/组件不得 import Element Plus；`main.ts` 清理后是唯一允许出现迁移说明的地方（代码不得保留 Element Plus）。
- 中文文案；PrimeVue 4；不新增 UI 依赖；不替换 MarkdownEditor/CodeEditor。
- 390px 窄屏表格容器内滚动；暗/亮主题都可用；`MarkdownEditor` 必须传入 `isDark ? 'dark' : 'light'`。
- 每个任务先写失败测试，再实现；完成后跑对应测试、全量 web 检查。

## Review Focus

1. **AI 入口与契约**：`TestcaseManager` 重写后 traditional 仍显示「AI 造数据」并 push 正确路由；special 不显示；props/emit 不变。测试：现有 AI 按钮测试保留并断言跳转。
2. **测试点行为**：上传、分数、样例标记、上移/下移、删除、checker 上传、请求竞态与 busy 禁用不回归。测试：`TestcaseManager.spec.ts` 覆盖每个操作与确认框 accept/cancel。
3. **题目编辑行为**：字段映射、标签/样例、公开开关、保存 edit/create、删除 offlined、失败恢复 `isPublic`、404/加载错误。测试：新增 `ProblemEditView.spec.ts`。
