# 学习路线详情页 · 算法之树视觉改版设计

> 日期：2026-11-13
> 范围：`/learning-paths/:id` 路线详情页（查看态）
> 参考效果图：[算法之树效果图](assets/2026-11-13-learning-tree-a.jpg)
> 关联文档：`docs/superpowers/specs/2026-11-05-m4-learning-paths-design.md`、`DEVELOPMENT.md` 3.8/4.5

## 1. 背景与目标

当前学习路线详情页使用 PrimeVue `TreeTable` + 右侧题目面板。数据模型已经是“算法节点 → 子算法 → 题目”的树，但表格形态无法直观表达“一棵树”的结构，也不够有学习路线的成长感。

本次改版把详情页做成一张可交互的算法之树：

- 每个路线是一棵从底部生长的树，树的骨架由真实节点树生成，不是固定图片。
- 算法节点是枝干上的发光节点；有子算法时继续分叉。
- 叶子节点（没有子算法）的题目以“题叶”形式挂在节点周围，可直接点击进入题目。
- 右侧“节点卷宗”展示节点描述、进度与完整题目清单。
- 已完成、进行中、未解锁三种状态直接改变节点、枝干与题叶的视觉。
- 移动端降级为纵向树（树干 + 枝干卡片 + 题叶），保留同一套视觉语言与信息层级，不横向挤压。

成功标准：用户进入路线后，第一眼能看懂“我现在走到哪、下一步去哪、这个节点有哪些题”；视觉上确实是一棵树，而不是换了皮肤的表格。

## 2. 非目标

- 不改学习路线列表页 `/learning-paths`。
- 不改编辑页 `/learning-paths/new`、`/learning-paths/:id/edit`，节点编辑器继续使用现有 `TreeTable`。
- 不改官方管理页 `/admin/learning-paths`。
- 不改服务端进度语义、解锁规则、完成锁存、题目下线守卫。
- 不做拖拽节点、自由缩放/平移、缩略图、节点评论、学习计划或提醒。
- 不引入新的前端依赖、图表库或位图树背景。
- 不做路线分享卡片、封面生成。

## 3. 已确认决策

1. 采用效果图中的 **A 算法之树**：底部主干、向上分叉、节点为发光圆章、题目为叶。
2. 树的背景由节点树实时生成：不同路线因为结构不同，自然得到不同的树；同一路线每次渲染形状稳定。
3. 详情页保留右侧节点卷宗；移动端改为节点卡片内联展开的卷宗，不使用全屏遮罩。
4. 题目叶子只在**叶子算法节点**（没有子节点）上展开；有子节点的算法节点显示题目数徽标，完整题目清单仍在卷宗中展示。这样避免题叶和子算法枝干互相遮挡。
5. 默认选中第一个 `active` 节点；没有 `active` 时选中第一个根节点；没有节点时不选中。
6. 游客行为与现状一致：根节点 `active`、其余 `locked`、进度为 0；游客可以浏览节点与题目，不写进度。
7. 锁定节点仍可查看卷宗与题目链接（现有产品行为是软引导，不是硬门槛）；视觉上明确标注“未解锁”。
8. 主题同时支持深色/浅色；视觉以深色为主，浅色使用同一套 token 的低对比版本。
9. 新增题目级 `solved` 字段，用于题叶通过态与“继续挑战”选择下一题；不改变节点聚合进度与完成锁存。

## 4. 方案对比与选择

| 方案 | 描述 | 取舍 |
|------|------|------|
| A 算法之树（选用） | 一棵从底部生长的树，算法节点在枝干上，题目是叶子，右侧卷宗 | 最符合“一棵树”的诉求；需要实现布局算法与响应式降级 |
| B 技能星图 | 算法是行星、题目是卫星、前置关系是星座连线 | 游戏化最强；层级深/题目多时连线与卫星拥挤，隐喻偏“星图” |
| C 树干导航 | 左侧主干 + 枝干卡片 + 叶签 | 最稳、移动端最友好；视觉冲击弱，更像升级版列表 |

选择 A，因为用户的原始诉求就是“底图是一棵树、分支是算法、题目是叶子”。C 的交互与信息结构保留为移动端降级方案，保证小屏可用。

## 5. 页面结构

```text
AppPageHeader（标题、官方/公开标签、返回列表）
└─ 路线摘要条（作者、节点数、题目数、完成节点数、进度环）
└─ 路线简介（可选，path.descriptionMd 折叠展示，默认两行）
└─ AppSurface
   ├─ 桌面：树舞台（左） + 节点卷宗（右）
   │  ├─ 树舞台
   │  │  ├─ 工具栏：实时进度 / 交互提示
   │  │  ├─ 背景层：树干、枝干、树冠、微光、网格
   │  │  ├─ 连线层：按状态着色的 SVG 枝干
   │  │  ├─ 节点层：算法圆章 + 标题 + 进度
   │  │  ├─ 题叶层：选中叶子节点的题目叶
   │  │  └─ 图例：已完成 / 进行中 / 未解锁 / 题目叶子
   │  └─ LearningNodePanel（标题、状态、描述、进度、题目清单、继续挑战）
   └─ 移动端：纵向树 + 选中节点内联卷宗
```

`path.descriptionMd` 是作者内容，不能因为改版丢失。桌面与移动端都在摘要条下方保留一个可折叠的“路线简介”：默认显示两行，点击“展开/收起”查看完整 Markdown；无描述时整个区块不渲染。该区块在树舞台之外，不占用舞台高度，页面整体自然滚动。

页面仍使用现有 `AppPageHeader`、`AppSurface`、`AppErrorState`、`AppLoadingState`、`MarkdownView`。树舞台不放在额外的卡片里，直接作为 `AppSurface` 的主内容区，保持沉浸感。

路线摘要条是本次新增的轻量信息区：

- 左侧：作者、`nodeCount` 个节点、题目进度、`myCompletedCount` 完成节点。
- 题目进度文案为 `已完成 X / Y 题`：按整条路线去重后的 `problemId` 统计，`X` 为 `problems[].solved === true` 的去重题目数，`Y` 为当前树中可见的去重题目总数；不把同一道题在多个节点里重复计数，也不使用可能因完成锁存而偏高的 `solvedCount` 相加。已下线题目不在 `problems` 中，因此不计入。
- 游客只显示 `Y 题`，不显示 `0 / Y`。
- 右侧：进度环（`myCompletedCount / nodeCount`）+ 百分比。
- 无节点时显示 `0 / 0` 与空态，不显示进度环动画。

## 6. 树形布局

### 6.1 布局算法

采用“翻转的 tidy tree”布局：根在底部，子节点向上生长，父节点水平居中于子节点。

1. 先对每个节点计算子树宽度：
   - 叶子节点宽度 = `NODE_SLOT_WIDTH`。
   - 有子节点的节点宽度 = 所有子节点宽度之和 + `SIBLING_GAP * (childCount - 1)`，但不小于 `NODE_SLOT_WIDTH`。
2. 递归分配 x：子节点按顺序从左到右排列；父节点 x = 第一个子节点与最后一个子节点的中点。
3. 根节点/多根森林：每个根子树并排，整体水平居中；多根之间额外增加 `ROOT_GAP`。
4. y 按深度计算：根在底部，`y = canvasHeight - PADDING_BOTTOM`；每向上一层 `y -= LEVEL_GAP`。
5. 画布尺寸 = 内容包围盒 + 四周 padding；`PADDING_TOP` 需要容纳题叶与树冠，`PADDING_BOTTOM` 容纳主干与图例。
6. 布局是纯函数，输入 `LearningPathNodeItem[]`，输出节点位置、画布尺寸、连线路径、每个节点的深度与子树宽度。相同输入必须得到相同输出。

建议初始常量（实现时可微调，但需满足不重叠与可读性）：

```text
NODE_SLOT_WIDTH  = 152
SIBLING_GAP      = 28
ROOT_GAP         = 56
LEVEL_GAP        = 126
PADDING_X        = 96
PADDING_TOP      = 112
PADDING_BOTTOM   = 84
NODE_SIZE_ROOT   = 60
NODE_SIZE_D1     = 54
NODE_SIZE_D2     = 46
NODE_SIZE_D3PLUS = 42
```

- 同一层节点之间的水平间距不得小于 `SIBLING_GAP` 的 80%，保证圆章与标题不重叠。
- 标题在节点下方，最大宽度 `150px`，单行省略；完整标题通过 `title` 属性与卷宗展示。
- 节点圆章中心对准枝干终点；枝干从父节点圆章中心画到子节点圆章中心，节点层覆盖在连线层之上。
- 枝干使用三次贝塞尔曲线：控制点位于父/子之间 40% 与 60% 的垂直位置，横向偏移根据两点 x 差自适应，避免所有线都像直线。
- **枝干颜色规则**：一条边的状态取**子节点**的状态（`completed` 绿、`active` 青、`locked` 灰虚线）；根节点到画布底部的主干取根节点状态。这样从根往上看，已完成的路径是绿色，当前可走的下一段是青色，未解锁的分支是灰色。不为每条边做双色渐变，避免混合状态难以判断。
- 根节点到画布底部画一段主干；多根时每个根各有一段主干，底部用一条很淡的地平线连接。

### 6.2 画布适配

- 树舞台视口高度：桌面 `min(680px, calc(100vh - 220px))`，最低 `560px`。
- 根据视口宽高计算 `fitScale`：
  - `fitScale = min(1, (viewportW - 32) / canvasW, (viewportH - 32) / canvasH)`。
  - `fitScale` 不低于 `0.7`；低于 `0.7` 时保持 `0.7`，允许横向/纵向滚动。
- 使用外层滚动容器 + 内层缩放容器：内层按 `canvasW/canvasH` 布局，`transform: scale(fitScale)`，外层滚动尺寸使用缩放后的宽高，保证滚动条正确。
- 缩放后画布小于视口时居中；大于视口时从左上开始，加载完成后自动把第一个 `active` 节点滚到视口中央。
- 切换路线时重置滚动位置与选中状态，再重新居中。
- 使用 `ResizeObserver` 监听舞台尺寸变化，重新计算 `fitScale`；组件卸载时断开。
- 不使用鼠标滚轮缩放；保留浏览器/触控板正常的滚动行为。

### 6.3 背景树

背景树不是一张固定图片，而是由布局结果生成的 SVG 装饰层：

- 主干：从底部到根节点，宽度随深度变细；使用深绿到墨色的渐变。
- 枝干：与真实连线同路径，但更粗、更低对比，形成“木质骨架”；真实状态连线叠在上面。
- 树冠：在深层节点附近生成低透明度、模糊的椭圆叶团；每个子树一簇，不能盖住节点文字。
- 微光：少量 1–2px 的光点，使用 `path.id` 作为确定性种子（例如 mulberry32）生成位置与延迟；同一路线稳定，不同路线不同。
- 网格：树舞台底部的细网格，使用遮罩在边缘淡出；浅色主题减弱或关闭。
- 所有装饰层 `aria-hidden="true"`、`pointer-events:none`，不参与点击与键盘焦点。

这样每条路线的树形骨架都由真实结构决定，同时保留“每棵树略有不同”的自然感。

## 7. 节点视觉与状态

### 7.1 圆章

- 圆章直径按深度递减：根 60px、一级 54px、二级 46px、三级及更深 42px。
- 圆章内部显示 1–3 个字符的算法符号：优先使用节点标题首字/首词缩写；没有合适缩写时显示 `•`。符号只是装饰，不替代标题。
- 圆章外圈叠加进度弧：
  - `completed`：完整绿色弧 + 右上角 `✓` 徽标。
  - `active`：按 `solvedCount/requiredCount` 的青色进度弧；未开始时为低亮青色虚线。
  - `locked`：灰色、低饱和、虚线弧；不显示进度数字，只显示“未解锁”标签。
- 节点标题在圆章下方，状态/进度用第二行小字：
  - 完成：`6 / 6`
  - 进行中：`2 / 4`
  - 未解锁：`未解锁`
- 有子节点且有题目时，在圆章右上角显示一个小叶徽标 `🍃 N`（用 CSS 叶形 + 数字，不使用 emoji），提示卷宗里有题目。

### 7.2 状态样式

| 状态 | 圆章 | 枝干 | 题叶 | 其他 |
|------|------|------|------|------|
| completed | 绿色边框、绿色进度弧、✓ 徽标 | 绿色实线，低亮度发光 | 绿色题叶、✓ | 标题正常亮度 |
| active | 青色边框、青色进度弧、柔和外发光 | 青色实线，轻微流动虚线 | 青色/灰色题叶 | 选中时外圈脉冲 |
| locked | 灰色边框、低饱和、虚线弧 | 灰色虚线、低透明度 | 灰色题叶、锁定图标 | 标题降亮度 |

**状态优先级**：节点状态（`completed`/`active`/`locked`）决定圆章、枝干、节点标签的样式；题目级 `solved` 决定题叶与卷宗题目行的通过态，两者独立。一个 `locked` 节点里可能已经有用户提前 AC 的题目，这些题叶仍显示绿色 ✓，未通过的题叶显示灰色；节点本身保持灰色“未解锁”。卷宗同样按题目逐行显示 `已通过/未开始`，不因节点锁定而隐藏通过态。这样既尊重“前置未完成”的路线状态，也准确反映用户已经做过的题。

- 颜色不是唯一信息：完成用 ✓、未解锁用锁图标、进行中在卷宗显示文字标签。
- 选中节点：圆章外再套一圈 1px 青色描边，外圈脉冲 2.8s；`prefers-reduced-motion: reduce` 时取消脉冲与流动。
- 悬停：圆章放大 `1.04`，标题提亮；不改变布局。
- 焦点：`focus-visible` 使用现有 `--kapoj-focus-ring`，焦点环在圆章外侧。

## 8. 题叶

### 8.1 显示规则

- 只看**叶子算法节点**（`children.length === 0`）：
  - 节点被选中时，在圆章上方或周围展开题叶。
  - 题目数量 1–5：全部展开。
  - 题目数量 > 5：展开 4 片 + 1 片 `+N`（点击 `+N` 聚焦卷宗题目列表）。
- 有子节点的算法节点：
  - 不在画布上展开题叶，只显示 `🍃 N` 徽标。
  - 卷宗仍展示该节点的全部题目（因为后端允许一个节点同时有子节点和题目）。
- 题叶位置：
  - 叶子节点在画布上方有足够空间时，以节点为圆心向上呈扇形展开（参考效果图）。
  - 如果节点靠近画布上边缘，自动改为在节点左右两侧展开，保证不裁切。
  - 题叶之间保持至少 6px 间距；实现时可以按固定槽位排布，不要求物理碰撞模拟。
- 题叶与节点之间画 1px 虚线“叶柄”，颜色与题叶状态一致。

### 8.2 题叶内容

```text
[叶形图标] 题目标题（最多 1 行，省略）  [难度点]
```

- 题目标题最多显示约 18 个字符，超出省略；完整标题在 `title` 属性与卷宗中。
- 难度用 1–5 个颜色点或 `难度 N` 小字；颜色沿用 `--kapoj-difficulty-*`。
- 已通过：绿色叶、✓；未通过：青色/灰色叶、空心点。
- 题叶的通过态与节点状态独立：`locked` 节点中已 AC 的题仍显示绿色 ✓，未通过的题显示灰色；节点本身仍是“未解锁”。
- 点击题叶直接进入 `/problems/:problemId`；使用 `RouterLink`，`@click.stop` 避免同时触发节点选中。
- 题叶是链接，键盘可 Tab 到达；焦点样式与普通链接一致。

### 8.3 题目级通过状态

现有接口只返回节点聚合 `solvedCount`，无法判断具体哪道题已通过。为了让题叶显示通过态、并让“继续挑战”选择下一道未通过题，新增：

- `LearningProblemSummary.solved: boolean`
  - 当前查看者是否在该题目上有 AC。
  - 游客恒为 `false`。
  - 不影响节点 `solvedCount` 与完成锁存；仅用于展示与“继续挑战”。
- 服务端在 `Tree` 中查询一次当前用户的 `AcceptedProblemIDs`，传入 `buildNodeTree`，为每个 `ProblemSummary` 填充 `solved`。
- 公开树（游客/其他用户）仍然只返回公开题目摘要；`solved` 只表达当前查看者自己的状态。
- OpenAPI 更新并重新生成前端类型。

如果后续认为这次不想改后端，降级方案是：题叶不显示通过态，只显示难度；“继续挑战”进入节点第一题。但本次设计按新增 `solved` 字段实施，因为它对“树上有叶子”的体验提升明显，且改动很小。

## 9. 节点卷宗

桌面端右侧固定宽度 `300px`，与树舞台同高，内部可滚动。移动端为选中卡片下方的内联卷宗。

内容顺序：

1. 顶部：`NODE // {序号}`、关闭/收起按钮（桌面可省略关闭，移动端用于收起卷宗）。
2. 状态行：状态标签（已完成/进行中/未解锁）+ `solvedCount / requiredCount`。
3. 标题（完整，不截断）。
4. 描述：`MarkdownView`，深色/浅色跟随主题；无描述时显示“该节点暂无描述”。
5. 进度条 + “已通过 X 题 / 还需 Y 题”；完成节点显示“完成时 X 题”。
6. 题目清单：
   - 每行：通过勾选/空心圆、题目标题（完整）、难度、`已通过/未开始`。
   - 行可点击进入题目；整行是链接。
   - 超过 8 题时列表内部滚动，保持卷宗高度稳定。
   - 无题目时显示“该节点暂无题目”。
7. 底部主按钮：
   - 有未通过题：`继续挑战` → 第一道 `solved === false` 的题。
   - 全部通过：`复习题目` → 第一题。
   - 无题目：禁用，文案“暂无题目”。
8. 锁定节点：显示提示“完成前置节点后推进进度；题目仍可提前挑战。”不阻止题目链接。锁定节点的圆章标签显示“未解锁”，但卷宗仍展示 `solvedCount / requiredCount` 与逐题通过态；按服务端规则，锁定节点的 `solvedCount < requiredCount`，因此“继续挑战”仍能定位到一道未通过题。

卷宗不显示原始 `problemIds`，只使用 `problems` 摘要；作者/管理员编辑入口仍在编辑页，不在详情页新增。

## 10. 响应式

### 10.1 桌面（≥ 1100px）

- 树舞台 + 300px 卷宗左右布局。
- 树舞台高度 620–680px；卷宗同高。
- 页面内容宽度沿用 `--kapoj-content-max`；树舞台占据剩余宽度。

### 10.2 平板（900–1099px）

- 卷宗宽度收窄到 280px。
- 树舞台按 `fitScale` 缩放，允许滚动。
- 标题字号与节点尺寸不下调，保证可读性。

### 10.3 移动端（< 900px）

不使用缩放画布，改为纵向树：

- 顶部保留 `AppPageHeader`（标题、官方/公开标签、返回列表）；其下是紧凑的路线摘要卡，只展示进度条、`已完成 X / Y 节点` 与 `已完成 X / Y 题`，不重复标题与作者，避免与页头信息重复。
- 路线简介折叠块保留在摘要卡下方。
- 纵向树：
  - 左侧 2px 主干线，按深度缩进；每个算法节点是一张枝干卡片。
  - 卡片包含：状态圆点、标题、状态标签、`solved / required`、进度条。
  - 选中卡片高亮；叶子节点在卡片内展开题叶（最多 4 片 + `+N`）。
  - 有子节点的卡片显示 `🍃 N` 题目徽标，不展开题叶。
  - 点击卡片选中；选中卡片下方内联展开卷宗（描述、完整题目列表、继续挑战）。
- 卡片点击区域 ≥ 44px；题叶点击区域 ≥ 36px。
- 不做横向滚动；长标题两行省略，完整标题在卷宗中。
- 移动端隐藏树舞台的图例与工具栏，保留状态图例在列表底部。

### 10.4 375px 验收

- 无横向溢出。
- 题叶、按钮、链接均可点击。
- 内联卷宗不遮挡卡片；展开后页面滚动到卷宗顶部。
- 状态标签与进度数字不换行错位。

## 11. 主题与视觉

### 11.1 Token

在 `apps/web/src/styles/tokens.css` 增加树专用 token（深色/浅色各一套）：

```text
--kapoj-tree-trunk
--kapoj-tree-branch
--kapoj-tree-branch-done
--kapoj-tree-branch-active
--kapoj-tree-branch-locked
--kapoj-tree-foliage
--kapoj-tree-grid
--kapoj-tree-glow
```

- 深色：墨绿树干、青色进行中、绿色完成、灰色锁定、低透明树冠。
- 浅色：浅灰绿树干、深青进行中、深绿完成、灰褐锁定；降低发光强度，避免脏灰。
- 节点圆章背景使用 `--kapoj-bg-elevated`/`--kapoj-surface`，不写死颜色。
- 题叶使用状态色的 10–14% 透明背景 + 1px 边框，文字使用状态色加深版本，保证对比度。
- 所有颜色必须来自 token 或 `color-mix`/rgba 变量；不在组件里散落硬编码品牌色。

### 11.2 动效

- 选中节点外圈脉冲、进行中枝干流动虚线、题叶展开淡入。
- 动画时长 160–280ms；`prefers-reduced-motion: reduce` 时全部关闭。
- 树舞台加载时不做整树生长动画，避免每次进入页面都等待；只做节点淡入。

### 11.3 装饰克制

- 背景树/树冠/微光不能抢节点与题叶的可读性；层级透明度上限 0.35。
- 节点文字、题叶文字必须始终在装饰层之上，并有足够对比度。
- 浅色主题下网格与微光默认关闭或降到极低。

## 12. 交互与可访问性

### 12.1 交互

- 进入页面：加载树 → 计算布局 → 默认选中第一个 `active` 节点 → 滚动到该节点。
- 点击节点：更新选中态与卷宗；不改变路由。
- 点击题叶：`RouterLink` 进入题目详情；`@click.stop`。
- 点击 `+N`：选中节点并让卷宗题目列表滚动到该题附近（或直接展开全部）。
- 卷宗内题目行：整行链接到题目。
- `继续挑战`：第一道 `solved === false` 的题；全部通过则第一题。
- 切换路线：清空选中、卷宗、滚动位置，重新加载。
- 错误/空态：保留现有文案与重试按钮。

### 12.2 键盘

- 树容器 `role="group"` + `aria-label="学习路线树"`。
- 每个节点是 `<button type="button">`，`aria-label` 包含标题、状态、进度：
  - 例：`滑动窗口，进行中，已完成 2 / 4 题，查看节点详情`。
- Tab 顺序按树的先序遍历（DOM 顺序），保证阅读顺序与视觉层次一致。
- Enter/Space 选中节点；题叶与卷宗题目使用普通链接的 Enter 行为。
- 焦点环在圆章外侧，不被 `overflow:hidden` 裁切。
- 选中变化通过 `aria-live="polite"` 的视觉隐藏文本播报：“已选择滑动窗口”。

### 12.3 语义与降级

- 装饰 SVG、树干、树冠、微光全部 `aria-hidden`。
- 树舞台在 CSS/JS 加载失败时仍保留节点按钮与卷宗文本（渐进增强）。
- 移动端纵向树是语义化列表：`<ol>` + `<li>`，层级用 `aria-level` 或嵌套列表表达。
- 颜色状态都有图标/文字兜底。

- 游客：`solved` 恒为 `false`。

## 14. 前端结构

### 14.1 新增/调整文件

```text
apps/web/src/components/learning/
  LearningTreeCanvas.vue        # 桌面树舞台：SVG 背景/连线 + 节点 + 题叶 + 图例
  LearningTreeNode.vue          # 单个算法圆章（可复用）

apps/web/src/views/
  LearningPathDetailView.vue    # 数据加载、选中态、桌面/移动切换、错误/空态
```

- 组件全部使用 `<script setup lang="ts">` 与 scoped CSS，遵循现有风格。
- `LearningNodePanel` 用同一个内容组件渲染桌面侧栏与移动端内联卷宗，避免两份题目列表逻辑。
- 使用 PrimeVue `Button`、`Tag`、`ProgressBar`、`Tooltip`（如已有使用习惯）；不新增依赖。
- 使用 `ResizeObserver` 计算 `fitScale`；测试环境已有 mock。
- 响应式判断使用 `window.matchMedia('(max-width: 899px)')` 或容器宽度；统一封装为 `useLearningViewport` 或在 `LearningPathDetailView` 内实现，需在组件测试中可注入/可 mock。
- 移动端与桌面端共用 `selectedNode`、`flattenLearningNodes`、`learningStatusLabel` 等现有工具；新增布局工具保持纯函数。

### 14.2 状态

```text
loading       加载中
error         404 / 其他错误
path          路线元信息
nodes         节点森林
selectedId    当前选中节点 id
selectedNode  计算属性
fitScale      桌面画布缩放
isMobile      响应式标记
```

- `selectedId` 在数据加载后设为第一个 `active` 节点；没有则第一个根节点。
- 选中节点在数据刷新后如果仍存在则保留；不存在则重新按默认规则选择。
- 切换 `route.params.id` 时重置全部状态，防止旧路线残留。

### 14.3 性能

- 布局在 `computed` 中按 `nodes` 缓存，避免每次渲染重复递归。
- 节点数量在 100 以内时保持流畅；超过 100 个节点仍应可用，允许滚动。
- 视觉发光使用 CSS `box-shadow`/渐变，避免每个节点一个 SVG filter。
- 背景树冠使用一个模糊滤镜层，不按节点重复滤镜。
- `ResizeObserver` 回调做 `requestAnimationFrame` 节流（如需要）；不要在高频滚动中重算布局。

## 17. 风险与取舍

- **布局复杂度**：tidy tree + 缩放 + 题叶可能产生边界情况；用纯函数与单元测试覆盖，常量可调。
- **深层/宽树**：最大深度 8，节点数无上限；通过最小缩放 + 滚动 + 自动定位缓解，不承诺一屏展示全部。
- **题叶与子节点冲突**：只让叶子节点展开题叶；内部节点的题目在卷宗中查看，保证树结构清晰。
- **移动端差异**：移动端不是同一张画布，而是纵向树；视觉语言一致，交互更稳。
- **API 变更**：`solved` 是新增必填字段，需要 OpenAPI/类型/前端同步；对现有客户端是向后兼容的增量字段。
- **视觉噪声**：背景树/树冠/微光容易过度设计；通过透明度上限、浅色降级、装饰层 `aria-hidden` 控制。
- **可访问性**：视觉树不是原生树控件；用按钮 + DOM 顺序 + aria-label + live region 保证可用，不实现完整的 roving tabindex/方向键导航（后续可增强）。
