- **文档更新**：`DEVELOPMENT.md` 2.1（版本说明）、2.3（仓库现状）、2.4（错误码）、3.1（实现差异）、4.1（关键接口与实现差异）、9（M0 状态）；`docs/任务清单.md` M0 全部任务。
- **实现差异**：
  - 业务接口统一挂在 `/api` 前缀下，`/health` 不加前缀。

  - `go.mod` 要求 Go 1.26（最新 go-redis、golang.org/x/* 依赖所需），符合规格「Go 1.22+」。
  - 本地 docker compose 中 PostgreSQL 映射到宿主机 5433、Redis 映射到 6380，避免与本机已有服务冲突。
- **待办**：

  - 修改密码接口未实现；吊销用户全部 refresh token 的能力（`RefreshStore.RevokeAll`）已具备。
  - 被封禁用户已签发的 access token 在过期前（最长 15 分钟）仍可使用。
  - 个人主页中的徽章、称号字段在 M3 前固定为空。

## 2026-11-04：M0 代码审查修复

- **变更内容**：根据 M0 全分支代码审查修复 3 个严重问题和 5 个重要问题，每个修复都先写出失败的测试再修改代码。
  - access token 过期后登出不会吊销 refresh token：`/auth/*` 不再经过 Bearer 校验，前端也不再向这些接口发送 access token。
  - 并发登录可绕过失败次数限制：改为校验密码前原子计数；用户名和邮箱登录共用同一个计数。
  - 修改资料会整行写回，可能撤销封禁、重置金币：新增 `UpdateProfile`，只写入修改的字段。
  - 多标签页会被随机登出：前端通过 `storage` 事件同步令牌，刷新失败时改用其他标签页已轮换的令牌。
  - 服务端 panic 返回无结构的 500：改为统一响应格式（50000）。
  - 补充并发注册同一用户名的数据库测试；提交遗漏的 `pnpm-lock.yaml`。
- **涉及模块**：用户与认证（4.1）
- **涉及文件**：`apps/server/internal/{auth/limiter.go,auth/service.go,user/repository.go,user/memory.go,user/service.go,router/router.go}`、`apps/web/src/{api/http.ts,stores/auth.ts}` 及对应测试
- **文档更新**：`DEVELOPMENT.md` 4.1「实现差异」（登录限制、`/auth/*` 鉴权、多标签页、资料更新）
- **实现差异**：登录或刷新时 Redis、数据库不可用返回 50000，而不是 50300（50300 只用于 `/health`）。
- **待办**（审查中的次要问题，暂缓处理）：
  - `Authorization` 头的 `bearer` 前缀应不区分大小写。
  - 登录的 `account` 字段应限制在 254 字节以内。
  - JWT 应强制要求 `exp` 声明。
  - Redis 中 `user_refresh:<id>` 集合会积累失效记录。
  - `.env.example` 中的示例密钥长度满足校验，误用时不会报错。
  - 头像链接允许 `http://`，在 HTTPS 页面会出现混合内容警告。
  - 资料编辑页在加载用户信息失败且无缓存时，表单为空且无提示。
