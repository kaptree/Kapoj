**RBAC-A（权限模型、Seed、解析与中间件，后端）已完成**：新增 `roles`、`permissions`、`role_permissions`、`user_roles`、`admin_audit_logs`、`rbac_meta` 模型/迁移；34 个权限码与 7 个内置角色；启动时首次 Seed 写入权限目录、内置角色权限并按 `users.role` 映射 `super_admin`/`problem_admin`/`contest_admin`，写 `rbac_meta.seed_version=1`；后续启动只按 code 自动补齐缺失的权限目录与内置角色（已有行不变），不恢复管理员删除的角色权限、不重新映射旧角色；`seed_version` 小于当前版本时同样只补齐目录/角色并更新版本，不会新增或恢复任何角色权限授权；给内置角色新增初始权限必须走显式数据迁移，不能依赖 seed。`rbac.Service.Access` 实时解析 active 用户、多角色权限并集与 super 标记；`RequirePermission`/`RequireAnyPermission` 实现 401/403 与 super 绕过；`GET /users/me` 返回 `roles`/`permissions`/`isSuperAdmin`。RBAC-A 只提供权限基础设施；角色管理 API（RBAC-B）与内容管理接口迁移（RBAC-C）已随后完成。验证：后端全量测试、`gofmt`、`go vet`、golangci-lint、评测与前端全量检查通过；真实启动冒烟验证 Seed 映射、`/users/me` 权限字段、权限变更即时性与重启幂等。

**RBAC-B（角色/用户/审计/统计 API，后端）已完成**：新增 `rbac` 角色/用户/审计/统计服务与 `adminapi` 包，挂载 `/api/admin/*`，全部使用 `RequirePermission`（super 绕过但仍写审计）。角色 CRUD/权限矩阵：`GET /admin/permissions`、`GET/POST /admin/roles`、`PUT/DELETE /admin/roles/:id`、`PUT /admin/roles/:id/permissions`；系统角色不可删除、code/name 不可改、`super_admin` 权限不可改，自定义角色 code 创建后不可改、权限整体替换并去重。用户管理：`GET /admin/users`（keyword/status/roleId 筛选）、`GET/PUT /admin/users/:id`、`PUT /admin/users/:id/roles`、`POST /admin/users/:id/ban|unban`；只有 super 能授予/移除/封禁/解封 super、禁止封禁自己、禁止移除/封禁最后一个 active super（事务 + advisory lock 串行化，含并发测试）。审计与统计：`GET /admin/audit`（actorId/action/targetType/日期筛选）、`GET /admin/stats`（计数 + 有 `admin.audit.view` 时附带最近审计）；敏感操作事务内写中文审计。移除旧 `userapi /admin/users`（避免与 adminapi 重复路由）。OpenAPI 已补充全部管理接口并重新生成前端类型。验证：后端全量测试、`gofmt`、`go vet`、golangci-lint、评测与前端全量检查通过；真实 API 冒烟覆盖权限即时生效、系统角色/super 保护、最后 super/自封禁、审计记录与临时数据清理。

**RBAC-C（内容管理接口权限迁移，后端）已完成**：题目、比赛、测评、游戏化、学习路线全部管理接口从 legacy role 迁移到 RBAC 权限码；`users.role`/JWT role 自 RBAC-C 起不再参与任何管理授权，仅保留展示/兼容。题库：`problem.view_hidden`（隐藏题读取）、`problem.create/update/delete`、`problem.publish`（修改 `isPublic` 需 `problem.update`+`problem.publish`）、`problem.testcase.manage`、`problem.checker.manage`；题解字段对拥有题目管理权限者可见。比赛：`contest.view_hidden/create/update/delete`、`contest.participant.read`、`contest.announcement.manage`；克隆用 `contest.create`。测评：`problem.view_hidden`（隐藏题提交）、`submission.view_live_contest`（赛时保护绕过）、`contest.update`（免报名比赛测试提交）。游戏化：成就/任务/徽章/称号各用 `gamification.*.manage`（`includeInactive` 同权限）；金币调整迁移到 `/api/admin/users/:id/coins`（`user.coins.adjust`，事务内审计）；`gamification.config` 仍公开只读。学习路线：`learning_path.official.manage`（写/管理官方与任意路线，保留内容管理员行为）、`learning_path.admin.read`（只读查看全部/下架/完整题目 ID）；作者规则保留。内容管理写操作（题目/比赛/游戏化/学习路线）经 `AuditAdminAction` best-effort 写审计，action 为权限码、target type 为 `problem`/`contest`/`gamification_*`/`learning_path`。OpenAPI 已更新全部权限码描述并重新生成前端类型。验证：后端全量测试、`gofmt`、`go vet`、golangci-lint、评测与前端全量检查通过；真实 API 冒烟覆盖各域权限独立、发布边界、旧角色不再授权、内容/金币审计与临时数据清理。

**RBAC-D（管理后台前端，2026-11-07）已完成**：新增统一 `/admin` 管理壳 `AdminLayout`/`AdminNav`（桌面侧栏 + 移动 Drawer）与仪表盘、用户管理、角色权限矩阵、审计日志四个页面；权限基础 `auth.can/canAny/isSuperAdmin` 与路由 meta `permission`/`anyPermission`（移除 `roles`）；菜单、路由、按钮全部按权限显隐，无权限直接访问 `/admin/*` 跳转 403；现有题目/比赛/游戏化按钮与 tab 改用 `auth.can`/`canAny`，游戏化按四个 `gamification.*.manage` 权限生成 tab；`AppNav`/`UserMenu` 管理入口改为 `/admin` 并按 `ADMIN_ACCESS_PERMISSIONS` 显隐；登录/注册/资料保存后刷新 `/users/me` 并保留 RBAC 字段，角色/权限变更后刷新即生效。验证：前端测试/lint/build、后端/评测全量检查通过；HTTP 冒烟覆盖仪表盘统计、用户管理（编辑/角色/调币/封禁/自封禁/最后 super）、角色权限矩阵（系统角色保护）、审计筛选、受限账号菜单/403、游戏化 tab 过滤与临时数据清理；真实浏览器 E2E 覆盖超管仪表盘/用户/角色/审计页面、受限账号菜单过滤与 403 重定向、游戏化单 tab、690px 移动 Drawer 与控制台无错误，并清理临时数据。
