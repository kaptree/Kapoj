# 数据备份与恢复

## 功能

- 全平台备份：数据库全部业务表、`StorageDir` 业务文件、`data/ai.key`/`data/mail.key`。
- 账号备份：完整单用户快照，或一个包含全部账号的包。
- 定时任务：每天/每周/每月，只保留最新一份成功包。
- 恢复：服务器最新包或上传 ZIP；全平台恢复前自动生成安全备份。

入口：管理后台 → 系统 → 数据备份（权限 `system.backup.manage`）。

## 配置

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `KAPOJ_BACKUP_DIR` | `<StorageDir>/backups` | 备份 ZIP、上传包与安全备份目录 |
| `KAPOJ_BACKUP_MAX_UPLOAD_BYTES` | 2 GiB | 上传恢复包大小上限 |
| `KAPOJ_BACKUP_MAX_UNCOMPRESSED_BYTES` | 20 GiB | ZIP 解压总大小上限 |
| `KAPOJ_BACKUP_MAX_ENTRIES` | 200000 | ZIP 条目数上限 |

备份目录不会进入全平台文件快照。生产环境应把该目录放在独立磁盘并限制文件系统权限。

## 恢复注意事项

建议在全平台恢复期间暂停 judge/其他写入服务，避免恢复窗口内仍有提交或后台任务写入数据库；管理后台会串行化备份/恢复任务，但不能阻止独立进程写入。

- 全平台恢复会替换数据库业务表与业务文件；恢复前自动生成 `safety/` 下的安全备份。后台入口要求输入 `RESTORE`，API 也校验同一确认字段。
- 全平台恢复要求数据库角色允许 `SET session_replication_role = replica`（当前 Docker 的 `kapoj` 用户满足）。
- 恢复成功后服务会自动 graceful shutdown 并重新执行自身；如果运行环境不允许 re-exec，需要配置进程管理器/容器重启策略兜底。
- 账号恢复按原 `user_id` 覆盖资料（含密码哈希）与个人数据；用户名/邮箱冲突会中止，不会静默合并。
- 账号备份不包含该用户创建的题目、比赛、学习路线、公告、任务等平台内容。
- 恢复包与数据库 schema 不一致时拒绝恢复，不会修改现有数据。
- ZIP 不加密，包含密码哈希与密钥文件，只能由可信管理员下载并妥善保管。

## 当前数据范围

账号备份包含用户资料、提交、金币流水、成就/任务/徽章/称号、登录记录、学习进度、购买/推荐、通知、关注、评价、证书、活跃/共享/Rating/比赛参与记录、题解互动、测试数据生成记录及头像/证书/生成文件。

## 常见失败

- “备份包与当前数据库 schema 不一致”：升级后不能使用旧版本备份直接恢复。
- “已有恢复任务正在执行”：恢复是全局串行操作，等待当前任务结束。
- “用户名或邮箱已被用户 N 占用”：账号恢复会保留原 user_id，但不会覆盖其他账号的身份字段。
