### 1.4 现状基线

本文基于 2026-11-14 当前代码核对，主要基线如下：

- 后端：Go + Gin + GORM + PostgreSQL，接口统一挂在 `/api` 下。
- 评测：独立 `apps/judge` 进程，Asynq 队列 + Docker 沙盒。
- 前端：Vue 3 + PrimeVue 4 + CodeMirror 6 + md-editor-v3，Markdown 渲染不依赖 CDN。
- 权限：RBAC，多角色 + 权限码；`super_admin` 绕过检查，`content_admin` 拥有全部 `problem.*`。
- 存储：本地文件系统 `KAPOJ_STORAGE_DIR`，通过 `storage.Storage` 抽象。
- 站点设置：`site_settings` 单例表，目前包含品牌、首页、页脚；后台页面 `/admin/site` 有“品牌 / 首页 / 页脚”三个 Tab。
- 金币：`coin_transactions` + `users.coins`，通过唯一约束 `(user_id, reason, ref_type, ref_id)` 做幂等。
- 学习路线：`learning_paths`、`learning_path_nodes`、`user_learning_progress` 已存在；支持官方/自定义、公开/私有、树状节点和服务端进度。
- 通知：`notifications` 表与 `/notifications` 页面已存在，页面已有“全部已读”和单条已读逻辑；铃铛未读数目前只靠 60 秒轮询。

## 3. 通用设计约定

### 3.1 权限与数据可见性

R04 会调整题库权限，后续 R03、R13 都依赖这套规则，因此先确定边界：

1. **管理员（全量题库管理）**
   - 新增权限码 `problem.manage_all`，含义是“可管理全部题目”。
   - `super_admin` 天然拥有；`content_admin` 增加该权限。
   - 拥有该权限的用户可以查看、编辑、发布、删除全部题目及其测试数据、附件。

2. **出题人（仅自己的题目）**
   - 新增内置角色 `problem_author`（出题人），默认权限：
     - `problem.create`
     - `problem.update`
     - `problem.publish`
     - `problem.delete`
     - `problem.testcase.manage`
     - `problem.checker.manage`
   - 不默认授予 `problem.view_hidden`、`problem.manage_all`。
   - 服务端在写操作前校验 `created_by = 当前用户`；列表只返回自己的题目（含未公开题）。
   - 出题人可发布/下线/删除自己的题目；发布/删除仍需遵守“有提交只能下线”、学习路线引用、付费路线题目等现有守卫。

3. **普通用户**
   - 只能看到公开题目；公开题详情、附件、提交统计可正常访问。
   - 隐藏题、测试数据、题面源文件不可见。

4. **隐藏题默认展示**
   - 出题人和管理员进入题库管理视图时，`includeHidden` 默认 `true`，默认看到自己的/全部未公开题。
   - 普通用户和游客不出现该开关，始终只看公开题。

5. **列表范围**
   - `GET /api/problems?scope=public|mine|all`
     - `public`：所有人可用，仅公开题。
     - `mine`：出题人/管理员可用，自己的全部题目（含隐藏）。
     - `all`：仅 `problem.manage_all` 可用，全部题目（含隐藏）。
   - 前端默认：管理员 `all`，出题人 `mine`，普通用户 `public`。

6. **详情可见性**
   - 公开题：所有人可见。
   - 隐藏题：创建者本人、`problem.manage_all`、`problem.view_hidden` 可见；其他人返回 40400，与不存在一致。
   - 测试数据与附件沿用同一可见性；测试数据额外只允许创建者/管理员查看。

### 3.2 金币与幂等

- 所有金币增减必须走 `coin_transactions`，并在同一事务内更新 `users.coins`。
- 重复奖励依赖唯一约束 `(user_id, reason, ref_type, ref_id)` 兜底，不允许只靠前端或内存判断。
- R06 的“通过题目奖励”必须保证：
  - 同一用户同一题目只发一次；
  - 重测、重复 AC、并发 AC 不重复发；
  - 金币不足、事务失败时不产生半成品流水。

### 3.3 文件存储与访问

- 测试数据属于私有文件，只能由出题人/管理员通过管理接口访问，不进入公开附件列表。
- 题目附件属于题目内容，公开题对所有访问者可见、可下载；隐藏题只对创建者/管理员可见。
- 题面图片属于附件的一种，但需要在 Markdown 中内联显示。
- 所有上传必须校验大小、类型、路径，禁止路径穿越；压缩包导入继续沿用现有 zip slip 防护。
- 文件下载建议统一带 `Content-Disposition: attachment`；图片内联接口单独提供，避免把任意附件当 HTML 执行。

### 3.4 前端约定

- 继续使用 PrimeVue 4，不引入依赖 CDN 的图表/编辑器。
- 图表优先使用现有自定义 SVG/CSS 能力，必要时再评估本地引入轻量图表库。
- 列表筛选条件继续写入 URL query，保证刷新、分享、返回时状态可恢复。
- 所有新增弹窗、拖拽区、排序按钮需要键盘可操作，并覆盖 375px 宽度。
- 代码、测试数据、题面内容继续走现有净化流程，不允许直接 `v-html` 未净化内容。

### 3.5 兼容与迁移

- 所有新增接口先更新 `packages/api/openapi.yaml`，再生成前端类型。
- 数据库变更使用迁移，不允许手工改线上表；历史数据需要给出回填策略。
- 新增权限码要同步权限目录、内置角色、前端 `permissions.ts`、权限矩阵页面与测试。
- 任何“默认值变化”（如题库默认显示隐藏题、站点徽章大小）要评估对现有用户的影响，并在开发日志记录“实现差异”。

## 4. 详细需求

### R01 评测记录详情增强

**优先级：P1　模块：测评记录　类型：功能增强**

#### 现状与问题

- `apps/web/src/views/SubmissionsView.vue` 的详情抽屉：
  - 题目标题是纯文本，不能跳转题目页；
  - 代码使用 `<pre>` 原样输出，没有语法高亮；
  - 测试点表格只有测试点编号、状态、耗时、内存、信息，没有分数列；
  - 没有“重测”入口。
- `GET /api/submissions/:id` 返回的 `judgeResult` 元素只有 `testcaseId/status/timeMs/memoryKb/message`，服务端 DTO 没有 `score`。
- judge 内部 `JudgeCaseResult.Score` 已存在，但序列化时被 `json:"-"` 排除，未落库到 `judge_result_json`。
- 当前没有重测接口。

#### 需求与规则

1. **重测**
   - 详情抽屉右上角或操作区增加“重测”按钮，点击二次确认；按钮仅对有权限的管理员显示。
   - 重测把该提交重新置为 `pending` 并重新入队，前端通过现有 SSE 自动刷新到终态。
   - 重测不改变提交代码、语言、题目、用户、比赛归属。
   - `pending`/`judging` 状态不允许重复点击；终态才显示可重测。
   - 权限（已确认）：仅拥有新增权限 `submission.rejudge` 的管理员可重测任意提交；普通用户（包括提交者本人）不显示重测按钮，也不能调用接口。
   - 比赛进行中他人提交受赛时保护，不能通过重测绕过代码/结果隐藏。
   - 防误触：同一提交 30 秒内最多重测一次，避免管理员连续点击刷队列。

2. **题目跳转**
   - 详情中的题目标题改为 `RouterLink`，跳转 `/problems/:problemId`。
   - 列表中的题目标题已经可跳转，保持现状即可。

3. **测试点分数**
   - 测试点表格增加“分数”列。
   - 表格底部显示总分，总分应与 `submission.score` 一致。
   - 历史提交的 `judge_result_json` 没有分数时显示“—”，不要用当前测试点配置反推，避免测试点已修改导致展示错误。

4. **代码高亮**
   - 代码区改为只读高亮组件，按语言选择 highlighter：
     - `c`/`cpp` → C/C++
     - `python3` → Python
     - `java` → Java
     - `go` → Go
     - `answer` → 纯文本/答案样式
   - 提供行号、复制按钮、横向滚动；长代码不撑破抽屉。
   - 不加载 CDN；使用项目已有的 `highlight.js` 或 CodeMirror 只读模式。
   - `codeHidden=true` 时继续显示赛时保护提示，不渲染代码。

#### 技术方案

**数据与接口**

- judge：`apps/judge/internal/model/model.go` 的 `JudgeCaseResult.Score` 改为可序列化（如 `json:"score,omitempty"`），并在 `Finish` 写入 `judge_result_json`。
- 服务端：`apps/server/internal/submission/model.go` 的 `JudgeCaseResult` 增加 `Score *int` 字段，JSON tag 为 `json:"score,omitempty"`，用于区分“历史记录无分数”和“真实 0 分”。
- `GET /api/submissions/:id` 自动返回新字段，无需新增查询参数。
- 新增 `POST /api/submissions/:id/rejudge`：
  - 请求体可为空；
  - 返回 `{id, status}`；
  - 事务内重置状态、清空 `time_used_ms/memory_used_kb/score/error_message/judge_result_json/judged_at`；
  - 入队失败时回滚为原状态或标记 `system_error`，不能留下永远 pending 的记录。
- 重测与 `accept_count`：
  - 当前 judge `Finish` 在 `judging -> accepted` 时无条件 `accept_count + 1`，重测 AC 会重复计数。
  - 建议给 `submissions` 增加 `accepted_counted boolean not null default false`，历史数据回填 `status='accepted'`。
  - 重测前若原提交是 AC 且 `accepted_counted=true`，先扣减题目的 `accept_count` 并置 false；新结果 AC 时由 judge 在事务内只加一次。
  - `submit_count` 不因重测变化。
- R06 的金币奖励也必须依赖幂等，不允许因重测重复发币。

**前端**

- 新增 `CodeViewer.vue`，封装语言映射、高亮、行号、复制。
- `SubmissionsView.vue` 详情抽屉：
  - 题目标题改为 `RouterLink`；
  - 代码区替换为 `CodeViewer`；
  - 测试点表增加分数列与总分；
  - 增加重测按钮、确认弹窗、加载态与 Toast。
- 重测成功后直接依赖现有 SSE 刷新；若 SSE 不可用，补一次详情请求。

#### 验收标准

- [ ] 有权限的管理员在终态提交详情看到“重测”，点击后状态变为等待评测，并在评测完成后自动更新；普通用户看不到按钮。
- [ ] `pending`/`judging` 提交不可重复重测；普通用户和无权限管理员看不到/调不通重测接口。
- [ ] 重测不会改变提交代码、语言、归属；不会重复增加 `submit_count`，`accept_count` 保持正确。
- [ ] 题目标题可跳转到题目详情。
- [ ] 测试点表格显示每个测试点分数和总分；历史无分数记录显示“—”。
- [ ] 代码按语言高亮、有行号和复制按钮，不请求 CDN；`codeHidden` 时仍隐藏。
- [ ] 后端、judge、前端测试通过；补充至少一个真实浏览器 E2E。

#### 已确认与剩余待确认

- 已确认：仅拥有 `submission.rejudge` 的管理员可重测；普通用户（含提交者本人）不可重测。
- 已确认：允许管理员重测 AC 提交；重测不重复发 AC 金币。
- 默认：同一提交 30 秒内最多重测一次，防误触；如需完全放开可在实施时调整。

### R03 题包导入与测试数据批量上传

**优先级：P1　模块：题库导入/测试数据　类型：功能增强**

#### 现状与问题

- 现有导入接口 `POST /api/problems/import/hydro` 只支持 HydroOJ 目录结构。
- 测试数据只识别同名 `.in` + `.out`，不识别 `.ans`。
- slug 冲突时直接失败，不询问用户是否覆盖。
- 前端 `ProblemImportView.vue` 只有文件选择，没有拖拽上传。
- `TestcaseManager.vue` 只能一次上传一对输入/输出文件，不能批量拖入多个文件。
- 没有“批量上传测试数据”的接口。

#### 需求与规则

1. **题目 ID 冲突与覆盖**
   - 导入题目使用 `problem.yaml` 所在目录名生成 slug，slug 是题目的稳定标识；数据库自增 ID 由系统生成，导入时不存在“指定 ID”概念。本文把需求中的“题目 ID 已存在”理解为“slug/题目标识已存在”。
   - 导入前先做冲突检测：
     - 返回冲突列表：`slug`、导入标题、已存在题目 ID、标题、当前用户是否有权覆盖。
     - 用户可以选择“逐项覆盖 / 全部覆盖 / 全部跳过”。
   - 覆盖权限：
     - 题目创建者本人，或拥有 `problem.manage_all` 的管理员；
     - 其他人的题目不能覆盖，只能跳过。
   - 覆盖范围：
     - 题面、标题、标签、时间/内存限制、测试数据；
     - 保留题目数字 ID、创建者、提交记录、提交/通过统计；
     - 覆盖后题目强制下线，需管理员确认后重新发布，避免测试数据变化影响线上。
   - 覆盖操作要写审计；整包级错误继续沿用现有回滚策略，不残留半套数据。

2. **测试数据文件识别**
   - 支持以下配对：
     - `1.in` + `1.out`
     - `1.in` + `1.ans`
   - 扩展名大小写不敏感（`.IN`、`.ANS` 也识别）。
   - 每个 `.in` 必须且只能配一个输出文件。
   - 同名 `.ans` 与 `.out` 同时存在时，已确认自动使用 `.out` 作为标准答案，并在导入结果中提示“同时存在 .ans/.out，已使用 .out”。
   - 只有 `.in` 没有输出、只有输出没有 `.in`、多个 `.in` 同名等情况，单题失败并给出明确原因。

3. **拖拽导入**
   - 导入页的文件选择卡片支持：
     - 点击选择；
     - 把 zip/tar.gz 拖入卡片；
     - 拖入时高亮，离开/释放后恢复；
     - 显示文件名、大小、清除按钮；
     - 键盘可聚焦、回车打开文件选择。
   - 前端先校验扩展名和 200 MiB 上限，后端继续做最终校验。
   - 拖拽不能触发浏览器打开文件。

4. **编辑题目时批量上传测试数据**
   - `TestcaseManager` 增加批量上传区，支持一次拖入/选择多个 `.in`、`.out`、`.ans` 文件。
   - 前端按 basename 分组，展示配对预览：
     - 已配对：`1.in ↔ 1.out`；
     - 缺失输出、重复输入、重复输出标红；
     - 存在未配对文件时，“保存/上传”按钮禁用，并提示“每个 .in 必须对应一个 .ans 或 .out”。
   - 批量上传默认分数 10、非样例；上传后仍可在表格中改分数、样例标记、排序。
   - 服务端必须再次校验配对，不能只依赖前端；建议一次最多 100 对、总大小不超过 200 MiB。
   - 批量上传要么全部成功，要么失败后清理已写入文件并返回错误，不能只入库一半。

#### 技术方案

**导入接口**

- 继续使用 `POST /api/problems/import/hydro`，增加 multipart 字段：
  - `conflictPolicy`：`ask` / `skip` / `overwrite`，默认 `ask`；
  - `overwriteSlugs`：JSON 数组，逐项覆盖时使用；
  - `skipSlugs`：JSON 数组，逐项跳过时使用。
- `conflictPolicy=ask` 且存在冲突时：
  - 不写库；
  - 返回 200，body 包含 `conflicts` 列表与 `imported=[]`；
  - 前端弹窗让用户选择后，携带同一文件重新提交。
- 覆盖时校验权限，逐题事务；单题失败进入 `failed`，不阻断其他题。

**批量测试数据接口**

- 新增 `POST /api/problems/:id/testcases/batch`（multipart，字段 `files` 可多个，`score` 可选，默认 10，`isSample` 可选）。
- 服务端解析文件名，按 basename 配对 `.in` 与 `.out`/`.ans`；全部校验通过后再写入。
- 写入顺序：先写存储，再写 DB；DB 失败时删除本次新写文件。
- 现有单对上传接口继续保留，兼容旧前端。

**前端**

- `ProblemImportView.vue`：拖拽卡片 + 冲突对话框 + 导入结果分组（成功/失败/跳过）。
- `TestcaseManager.vue`：批量拖拽区 + 配对预览 + 上传进度/失败原因。
- 文件选择 `accept` 增加 `.ans`；单对上传也接受 `.ans`。

#### 验收标准

- [ ] 导入 `.in/.out` 和 `.in/.ans` 都能成功，测试点数量、分数、顺序正确。
- [ ] `.in` 缺少输出、输出缺少输入、重复配对时不能保存，并显示具体文件。
- [ ] slug 冲突时出现覆盖选择；有权限可覆盖，无权限只能跳过。
- [ ] 覆盖后题目 ID、提交记录保留，题目变为下线，统计不清零。
- [ ] zip 可拖入文件卡片；拖拽、点击、键盘操作都能完成选择。
- [ ] 编辑题目时可批量拖入多对文件，配对完整才允许上传；上传失败不产生半套测试数据。
- [ ] 导入/批量上传的大小限制、路径穿越防护、部分成功与回滚测试通过。

#### 已确认与剩余待确认

- 已确认：“题目 ID”指导入生成的 slug；数字 ID 由系统生成，不支持按数字 ID 指定覆盖目标。
- 已确认：覆盖范围为题面 + 测试数据；保留题目数字 ID、创建者、提交记录与统计。
- 已确认：覆盖后题目强制下线，需管理员确认后重新发布。
- 已确认：同名 `.ans` 与 `.out` 同时存在时，使用 `.out` 作为标准答案，并在导入结果中提示。
- 剩余待确认：批量上传一次最多多少对、总大小上限；本文默认 100 对 / 200 MiB。

### R04 题目测试数据、附件与出题人权限

**优先级：P1　模块：题库/权限/文件　类型：新功能 + 权限调整**

#### 现状与问题

- 当前题目只有测试数据（`problem_testcases`），没有“公开附件”概念。
- 题面图片上传被禁用：`MarkdownEditor.vue` 排除了 `image` 工具条并设置 `no-upload-img`，没有粘贴上传能力。
- 题目详情页右侧只有官方题解、解题思路、提交统计、关联比赛四类资源卡片，没有附件卡片。
- RBAC 目前用全局 `problem.update` 等权限控制，没有“出题人只能改自己的题”的 ownership 校验。
- `ProblemListView.vue` 的 `showHidden` 默认 `false`；`includeHidden` 需要 `problem.view_hidden`，出题人看不到自己的隐藏题。
- 普通用户/出题人/管理员在题库页没有清晰的范围区分。

#### 需求与规则

1. **两类文件**
   - **测试数据**：评测使用，普通用户不可见；只有题目创建者、`problem.manage_all`、拥有对应管理权限且满足 ownership 的用户可管理。
   - **题目附件**：题目详情页展示，公开题对所有访问者可见、可下载；例如样例文件、PDF、图片、数据包等。
   - 测试数据永远不能通过附件接口下载；附件也不能被 judge 当作测试数据使用。

2. **题面图片粘贴上传**
   - 出题人在题目内容编辑器内粘贴图片（剪贴板 `image/*`）时，自动上传到当前题目，插入 Markdown 图片语法。
   - 编辑器工具栏提供“上传图片”按钮，行为与粘贴一致。
   - 上传中显示占位/加载态，失败给出错误，不插入坏链接。
   - 图片保存为题目附件的一种（`kind=statement_image`），与普通附件分开管理。
   - 新建题目在首次保存前还没有题目 ID，建议提示“请先保存题目，再上传图片”；或者保存后自动转为编辑态。本文采用“先保存再上传”，实现简单且不会产生孤儿文件。

3. **附件管理**
   - 题目编辑页新增“附件”区域：
     - 上传/拖拽多个文件；
     - 列表展示文件名、大小、类型、上传时间；
     - 复制下载链接；
     - 删除（二次确认）。
   - 题目详情页新增“附件”资源卡片：
     - 有附件时才显示；
     - 文件名可点击下载；
     - 显示大小；
     - 不显示存储路径。
   - 附件下载响应带 `Content-Disposition: attachment`；图片内联接口单独提供。

4. **权限**
   - 按第 3.1 节执行：管理员全部，出题人仅自己，普通用户仅公开题。
   - 已确认：出题人可发布/下线/删除自己的题目；发布/删除仍需遵守有提交只能下线、学习路线引用、付费路线题目等守卫。
   - 所有附件、图片、测试数据写操作都要校验 ownership；不能只靠前端隐藏按钮。
   - 题库管理页默认开启“显示隐藏题”；出题人默认“我的题目”，管理员默认“全部题目”。

#### 技术方案

**数据模型**

```sql
problem_attachments (
  id, problem_id, kind,           -- attachment / statement_image
  filename, storage_key, content_type, size,
  created_by, created_at
)
-- index (problem_id, kind)
-- storage_key 不返回前端
```

- 复用 `storage.Storage`，存储键建议：
  - 普通附件：`problems/<id>/attachments/<random>`
  - 题面图片：`problems/<id>/assets/<random>.<ext>`
- 删除附件时先删 DB 记录，再 best-effort 删文件；文件删除失败只记日志，不阻断。

**接口**

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/problems?scope=public\|mine\|all&includeHidden=` | 按范围 | 题目列表；`mine/all` 需登录与对应权限 |
| GET | `/api/problems/:id/attachments` | 题目可见 | 附件列表 |

| GET | `/api/problems/:id/assets/:aid` | 题目可见 | 内联读取题面图片 |

- 附件大小建议 20 MiB/个；题面图片 5 MiB/个，仅 PNG/JPEG/WebP/GIF。
- 普通附件允许常见文档、压缩包、文本、PDF；如果允许 HTML/SVG，必须强制下载，避免 XSS。
- 隐藏题的题面图片使用不可猜测的随机存储键，公开只读；如果要求严格鉴权，需要签名 URL 或带 token 的图片代理，建议作为后续增强。

- 学习路线列表只有“全部/官方/自定义/我创建的”筛选，没有关键词搜索和时间筛选。
- 详情页没有购买入口、参与人数、推荐人数、推荐按钮。
- 付费路线引用的题目在题库中的可见性没有规则。

#### 需求原文与理解

> “对于有费用的题目在题库中则是隐藏，且无法公开。”

结合上下文，已确认按以下含义实现：

- “有费用的题目”指“付费学习路线所引用的题目”。
- 付费路线引用的题目在题库中隐藏，且不能被设为公开，防止用户绕过付费路线直接刷题。
- 免费路线不受影响。
- 已购买该路线的用户仍可通过路线树访问题目；管理员/创建者始终可访问。

如果产品原意不是这个，需要在评审时纠正。

#### 需求与规则

1. **价格与购买**
   - 创建/编辑学习路线时可以填写“付费金币”，默认 0，即免费。
   - 价格范围建议 0–1,000,000；整数。
   - 只有路线创建者或 `learning_path.official.manage` 可以修改价格；官方路线默认 0，管理员可改。
   - 其他用户通过金币购买进入学习：
     - 免费路线：无需购买；
     - 作者、管理员：免费访问；
     - 已购买：幂等，不重复扣费；
     - 余额不足：40001，事务回滚；
     - 价格修改不影响已购买用户，不退款。
   - 未购买用户可以看到路线元信息（标题、作者、简介、价格、参与/推荐数），但不能读取树内容；详情页显示购买 CTA。
   - 购买成功后写入购买记录与金币流水，刷新用户余额。

2. **付费路线题目隐藏**
   - 付费路线（`price_coins > 0`）引用的题目必须是未公开状态。
   - 把公开题加入付费路线、把免费路线改为付费、或把付费路线题目设为公开时，返回 40001，并列出冲突题目。
   - 题目被任一活跃付费路线引用期间，禁止发布/公开；从所有付费路线移除后允许重新发布。
   - 如果题目同时被免费路线引用，改为付费路线时要提示冲突，不能静默改状态。
   - 管理员操作也要遵守该规则，除非产品明确允许管理员强制公开。

3. **参与人数与推荐**
   - 每个学习路线外侧（列表卡片）和内部（详情页）都显示：
     - 参与用户数；
     - 推荐数。
   - 详情页有“推荐”按钮：
     - 登录用户可推荐；
     - 每个用户对同一路线只能推荐一次；
     - 再次点击可取消推荐（建议做成 toggle）；
     - 不能推荐自己的路线；
     - 未购买/无权访问付费路线的用户不能推荐；
     - 推荐数实时更新。
   - 参与人数定义建议：
     - 付费路线：购买用户 + 有进度的用户（去重）；
     - 免费路线：有学习进度的用户（首次产生进度即算参与）；
     - 作者/管理员浏览不算参与，除非产生进度；
     - 如需统计“打开过路线”的用户，需要新增浏览记录，本文暂不实现。

4. **排序规则**
   - 普通用户不能编辑排序。
   - 官方路线始终排在用户路线前面。
   - 用户创建的路线自动追加到自己的序号后面；建议创建时自动分配 `sort_order = max(sort_order)+1`，前端不显示排序输入。
   - 管理员可以在后台管理页调整任意路线的 `sort_order`，包括官方路线。
   - 列表排序：`is_official DESC, sort_order ASC, created_at DESC`。
   - 服务端对普通用户的 `sortOrder` 字段忽略或返回 40001；不能只靠前端隐藏。

5. **搜索与时间筛选**
   - 学习路线列表增加关键词搜索：
     - 匹配标题、简介（可选作者昵称）；
     - 不区分大小写，按字面量匹配，转义 `%`/`_`。
   - 增加时间筛选：
     - 按创建时间范围筛选；
     - 支持开始日期、结束日期；
     - 日期参数用 ISO 日期，服务端按 UTC 解析，前端显示本地日期；
     - 开始/结束可以只填一个。
   - 与现有“全部/官方/自定义/我创建的”筛选组合使用。
   - 筛选条件写入 URL query，刷新可恢复。

#### 技术方案

**数据模型**

```sql

  ADD COLUMN price_coins bigint NOT NULL DEFAULT 0,
  ADD COLUMN participant_count int NOT NULL DEFAULT 0,
  ADD COLUMN recommend_count int NOT NULL DEFAULT 0;

CREATE TABLE learning_path_purchases (
  id, user_id, path_id, price_paid, created_at
);
-- unique(user_id, path_id), index(path_id)

CREATE TABLE learning_path_recommendations (
  id, user_id, path_id, created_at
);
-- unique(user_id, path_id), index(path_id)
```

- `price_coins` 校验 0–1,000,000。
- `participant_count`/`recommend_count` 为冗余计数，购买/首次进度/推荐/取消推荐时事务内更新；提供重建 SQL/命令，防止计数漂移。
- 历史路线默认价格 0、计数 0；上线后按购买/进度/推荐重新计算或懒更新。

**接口**

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/learning-paths?keyword=&createdFrom=&createdTo=&scope=&page=&page_size=` | 公开 | 列表；返回价格、参与/推荐数、是否已购买 |

- `PathItem` 增加：
  - `priceCoins`

### R12 后台云服务器部署设置

**优先级：P2　模块：站点设置/部署　类型：新功能**

#### 现状与问题

- `site_settings` 与 `/admin/site` 目前只有品牌、首页、页脚，没有部署域名配置。
- 当前前端使用相对 `/api`，图片/附件默认同源；没有统一的 CDN/资源域名配置。
- 没有任何后台页面记录主站域名、API 域名、CDN 域名等部署信息。

#### 需求与规则

- 后台站点设置新增“部署”Tab，至少支持填写：
  - 主站域名 `siteDomain`（必填，如 `https://oj.example.com`）；
  - API 域名 `apiDomain`（可选，留空表示同源）；
  - CDN 域名 `cdnDomain`（可选，如 `https://cdn.example.com`）；
  - 资源/附件域名 `assetsDomain`（可选，留空回退 CDN）；
  - 是否强制 HTTPS `forceHttps`；
  - 部署备注 `notes`（可选，最多 500 字）。
- 域名校验：
  - 必须是 `http://` 或 `https://` 开头的合法 URL；
  - 不允许尾部 `/`（保存时归一化去掉）；
  - 不允许包含查询参数、锚点；
  - `forceHttps=true` 时，主站/API/CDN 建议使用 `https://`，可给警告而非硬拒绝。
- 保存后写审计，权限 `site.settings.manage`。
- 这些配置用于：
  - 生成站内绝对链接（邮件验证、密码重置、通知等，若现有代码使用相对链接则逐步接入）；
  - 前端静态资源/图片/附件的 CDN 前缀（配置后使用，未配置回退同源）；
  - 运维查看当前部署域名。
- **不存储云厂商 AccessKey/Secret、数据库密码、JWT 密钥等敏感信息**；这些继续走环境变量/密钥管理。
- 该页面只维护配置，不执行真正的云服务器开通、DNS 解析、证书申请或 CDN 刷新；这些仍由运维完成。可在页面提供“部署检查清单”文案。

#### 技术方案

- `site_settings` 增加 `deployment_json jsonb not null default '{}'`，或拆成独立列；建议 JSONB 便于扩展。
- DTO：

  ```json
  {
    "siteDomain": "https://oj.example.com",
    "apiDomain": "https://api.example.com",
    "cdnDomain": "https://cdn.example.com",
    "assetsDomain": "",
    "forceHttps": true,
    "notes": ""
  }
  ```

- 接口：
  - `GET /api/admin/site/deployment`（`site.settings.manage`）
  - `PUT /api/admin/site/deployment`（`site.settings.manage`，写审计 target=`site_settings`）
  - 如前端需要读取 CDN 域名，可在 `GET /api/site` 返回 `deployment` 的公开子集（建议只返回 `cdnDomain/assetsDomain`，不返回备注）。
- 前端 `AdminSiteView.vue` 增加“部署”Tab：
  - 表单 + 域名预览；
  - 保存/重置；
  - 错误提示；
  - 可复制当前配置为文本，方便运维。
- 静态资源 URL 拼接：
  - 新增 `resolveAssetUrl(path)`：有 CDN/资源域名则拼接，否则返回原相对路径；
  - 先接入徽章、头像、题目附件/图片、站点 Logo/favicon；
  - 注意跨域：CDN 需要允许图片跨域（如需 canvas 处理），附件下载需要正确 `Content-Disposition`。

#### 验收标准

- [ ] 后台“部署”Tab 可填写并保存域名、CDN、强制 HTTPS、备注。
- [ ] 非法 URL、带查询参数、带尾部 `/` 被归一化或拒绝。
- [ ] 保存后刷新仍存在，写审计。
- [ ] 配置 CDN 后，徽章/头像/附件/Logo 等资源按配置拼接；未配置回退同源。
- [ ] 页面明确提示“不保存云厂商密钥”，不出现敏感字段。
- [ ] 权限测试、URL 校验测试、前端表单测试通过。

### R13 测试数据在线查看、编辑与新建

**优先级：P1　模块：题库测试数据　类型：功能增强**

#### 现状与问题

- `TestcaseManager.vue` 目前只能：
  - 上传一对输入/输出文件；
  - 修改分数、样例标记；
  - 排序、删除。
- 测试数据内容存在存储里，管理接口只返回元信息（文件名、大小、分数、顺序等），没有读取/编辑内容的接口。
- 没有“在线创建测试点”的弹窗。

#### 需求与规则

1. **在线查看/编辑**
   - 创建者/管理员在测试点表格点击“查看/编辑”，打开弹窗。
   - 弹窗左侧输入数据，右侧输出数据，等宽字体，纯文本，不需要富文本。
   - 显示测试点编号、分数、样例标记、文件大小。
   - 保存后写回存储，列表大小更新；失败不覆盖原文件。
   - 只读用户（有查看权限但无编辑权限）可查看但保存按钮禁用；本期先只对创建者/管理员开放，简化权限。

2. **在线新建**
   - 点击“在线创建测试点”打开同一个弹窗（新建模式）。
   - 左侧输入数据，右侧输出数据；下方可设置分数（默认 10）与样例标记。
   - 保存后新增测试点，按当前最大顺序追加。
   - 输入/输出都必须是文本；二进制文件请走文件上传。

3. **大小与安全**
   - 在线编辑只支持文本，建议单文件最大 2 MiB；超过时提示“文件过大，请下载/替换文件”，不把超大内容塞进浏览器。
   - 允许空输入/空输出（某些题目合法），但两个字段都必须提交。
   - 保存时先写新文件，再更新 DB，成功后删除旧文件；DB 失败时清理新文件。
   - 权限：创建者/管理员；隐藏题同样适用。
   - 测试数据内容永远不出现在公开接口。

#### 技术方案

**接口**

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/problems/:id/testcases/:tid/content` | 创建者/管理员 | 返回 `{input, output, inputSize, outputSize, score, isSample}` |
| PUT | `/api/problems/:id/testcases/:tid/content` | 创建者/管理员 | 更新输入/输出文本；body `{input, output}` |
| POST | `/api/problems/:id/testcases/online` | 创建者/管理员 | 在线新建；body `{input, output, score, isSample}` |

- 也可以复用现有 `POST /testcases` 的 multipart，由前端把文本转成 `File`；但为了校验和测试清晰，建议增加 JSON 接口。
- `GET content` 超过 2 MiB 时返回 40001，提示使用下载/替换；或返回 `tooLarge=true` 与元信息，不返回正文。
- `PUT content` 校验 UTF-8 文本、大小、两个字段都存在；写入新存储键，DB 更新成功后删除旧键。
- `POST online` 分数 0–1000，默认 10；`isSample` 默认 false；输入/输出大小上限与现有测试数据一致，但在线接口先限制 2 MiB。

**前端**

- 新增 `TestcaseEditDialog.vue`：
  - 左右两栏 `Textarea`（或 CodeMirror 纯文本只读/编辑），移动端上下堆叠；
  - 顶部显示测试点信息；
  - 底部“取消/保存”；
  - 未保存关闭时二次确认；
  - 加载中、保存中、错误态；
  - 大文件提示。
- `TestcaseManager.vue`：
  - 表格行增加“查看/编辑”按钮；
  - 工具栏增加“在线创建测试点”；
  - 保存成功后刷新列表并 emit `changed`。
- 现有单文件上传/批量上传（R03）继续保留；在线编辑与文件上传互补。

#### 验收标准

- [ ] 创建者/管理员可打开测试点查看输入/输出内容。
- [ ] 可修改并保存，刷新后内容、大小正确；旧文件被清理。
- [ ] 可在线新建测试点，左右分栏输入输出，分数/样例生效。
- [ ] 非创建者/非管理员看不到入口，直接调接口返回 403/404。
- [ ] 超过 2 MiB 的测试数据不能在线编辑，给出明确提示。
- [ ] 保存失败不破坏原测试数据；DB 失败清理新文件。
- [ ] 移动端弹窗可用，不横向溢出。
- [ ] 权限、大小、空内容、并发保存、文件清理测试通过。

#### 已确认与剩余待确认

- 已确认：在线查看/编辑单文件上限 2 MiB；超过时提示下载或替换文件。
- 已确认：允许空输入/空输出，由出题人自行保证评测正确性。
- 默认：弹窗提供“下载当前测试数据”按钮，方便大文件编辑。

## 6. 实施计划与依赖

### 6.1 阶段划分

| 阶段 | 内容 | 目标 |
| --- | --- | --- |
| A. 快速修复与展示统一 | R08、R09、R10、R02、R05 | 先修可见 bug，统一称号/徽章展示 |
| B. 题库权限与文件能力 | R04 → R13 → R03 | 先做出题人/管理员权限和附件基础，再做测试数据在线编辑与批量导入 |
| C. 评测与激励 | R01、R06、R07 | 完善评测记录、AC 金币、提交统计 |
| D. 学习路线与部署 | R11、R12 | 付费路线、推荐/参与数、搜索筛选、部署配置 |

### 6.2 关键依赖

- R03、R13 依赖 R04 的 ownership 与题目权限；不要先做出题人只能看自己题目的入口，却让接口仍可越权。
- R01 的重测依赖 R06 的幂等奖励与 `accept_count` 处理；两者要一起测试。
- R07 的代码长度依赖 `submissions.code_length` 迁移与回填。
- R11 的付费题目隐藏依赖 R04 的发布/下线校验；建议在 R04 中预留 `LearningGuard` 扩展点。
- R12 的 CDN 域名会影响附件/图片 URL 拼接；如果 R04 已完成，接入成本更低。

### 6.3 建议工作流

1. 每个阶段先补 OpenAPI 与数据库迁移，再写后端服务与测试。
2. 后端接口稳定后生成前端类型，再改页面。
3. 每个需求至少覆盖：
   - 后端单元/集成测试；
   - 前端组件测试；
   - 关键路径 E2E；
   - 权限负向测试（无权限、他人题目、隐藏题、赛时保护）。
4. 完成后按 `skills/dev-docs-sync/SKILL.md` 更新 `DEVELOPMENT.md`、`docs/任务清单.md`、`docs/开发日志.md`。

## 8. 已确认决策与剩余待确认项

### 8.1 已确认决策（2026-11-14）

| 编号 | 决策 |
| --- | --- |
| D1 | 出题人可发布、下线、删除自己的题目；仍需遵守有提交只能下线、学习路线引用、付费路线题目等守卫。 |
| D2 | 重测仅限拥有 `submission.rejudge` 的管理员；普通用户（含提交者本人）不可重测；允许重测 AC，重测不重复发 AC 金币；同一提交 30 秒内最多一次，防误触。 |
| D3 | 全站隐藏他人提交代码；查看者在同一道题有本人 AC 后可见；比赛进行中仍受赛时保护；统计页始终不展示代码、不提供代码入口。 |
| D4 | 题包导入的“题目 ID”指导入生成的 slug；覆盖题面 + 测试数据，保留数字 ID、创建者、提交记录与统计；覆盖后强制下线。 |
| D5 | 同名 `.ans` 与 `.out` 同时存在时，使用 `.out` 作为标准答案，并在导入结果中提示重复输出文件。 |
| D6 | 首次 AC 每题奖励 3 金币；不追溯上线前历史 AC；重测 AC 改成 WA 不扣回；练习、比赛、客观题都适用。 |
| D7 | 付费学习路线引用的题目在题库隐藏且禁止公开；从所有付费路线移除后可恢复公开。 |
| D8 | 学习路线参与人数按“购买 + 有学习进度”去重统计，单纯浏览不算。 |
| D9 | 徽章大小范围 16–48 px，默认 22 px，全站统一。 |
| D10 | 部署设置只做域名、CDN、资源域名、强制 HTTPS、备注；不保存云厂商密钥，不做一键部署/重启。 |
| D11 | 在线查看/编辑测试数据单文件上限 2 MiB；允许空输入/空输出。 |
| D12 | 称号统一为“【称号】昵称”，覆盖所有公开身份位置。 |
